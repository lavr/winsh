# winsh v0.1

A standalone Go CLI for running cmd.exe commands and PowerShell scripts over
WinRM with domain NTLM authentication. Public repository: github.com/lavr/winsh.
Apache-2.0. Project layout follows express-botx: main.go, internal/cmd, focused
internal packages, docs, examples, Makefile and release.sh.

## Contract

- `winsh run <host> [options] -- <command text ...>` runs cmd shell text. Tokens
  after `--` are joined with spaces; quote the entire command to preserve Windows
  quoting. Shell metacharacters are intentional, never interpreted locally.
- `winsh ps <host> [options] -- <script ...>` or `-f script.ps1` runs UTF-8 script
  input as a UTF-16LE EncodedCommand with no profile or interactive prompts.
- `--endpoint` overrides the host's network address; only HTTP(S) /wsman URLs,
  no embedded credentials, query or fragment. Default NTLM. `--target-host`
  sets the TLS certificate name for a tunnel. No built-in SSH orchestration.
- Password from WINRM_PASSWORD (or --password-env NAME) or --password-stdin;
  the latter reads one line. No interactive prompts, password flag, disk cache,
  HTTP trace, or password in diagnostic errors. No remote stdin in v0.1.
- stdout and stderr stream separately. PowerShell emits UTF-8. cmd output is
  unchanged by default; --codepage utf-8|866|1251 enables explicit decoding.
- The final command is limited to 8,000 UTF-16 code units (encoded invocation
  for PowerShell), reserving space below cmd.exe's 8,191 limit.
- Remote exit status is preserved, subject to the host OS exit status range.
  Local usage/config errors use 201, transport/protocol errors 202, timeout 203,
  cancellation 204. These can collide with remote statuses; stderr identifies
  local errors. No claim that Windows exit codes are globally reserved.
- Overall network/execution timeout defaults to 60s. Ctrl-C cancels work and
  cleanup gets a separate bounded timeout. TLS verification remains enabled.
- HTTP NTLM uses message sealing; no silent downgrade to unencrypted SOAP.
  HTTPS uses NTLM over verified TLS. No Kerberos, Basic, CredSSP or pass-the-hash.

## Components

`internal/cmd` validates input and dispatches a remote Request to Runner;
`internal/secret` reads credentials; `internal/remote` implements the WinRM
library adapter, context-aware HTTP transport, NTLM sealing, script encoding and
output decoding. main.go provides streams, signal context and process exit.

The protocol dependency is pinned using its declared historical module path
JohanVanosmaelAcerta/go-winrm through a replace
of masterzen/winrm because the fork still self-imports the original path.
Transport code owns HTTP contexts, response limits, redirect policy, and TLS.
NTLM cryptography is provided by established libraries, not implemented here.

## Validation and delivery

Tests cover argument boundaries, quoting, Unicode, credential handling, exit
codes, HTTP errors, cancellation, TLS verification, sealed message framing and
a simulated WSMan server. An opt-in live test uses an explicitly configured
Windows endpoint and reports a skip otherwise. Cross-build with CGO_ENABLED=0
for linux/amd64, linux/arm64, darwin/arm64, windows/amd64. GitHub Actions checks
formatting, vet, tests and race detection; tagged releases create archives and
SHA256SUMS through release.sh. No release tag until live validation.

## Later versions

Inventory, JSON output, probe and services; file transfer; Kerberos and channel
binding; optional SMB. The CLI must reject unsupported options instead of
pretending they work. All examples use generic hosts and domains.
